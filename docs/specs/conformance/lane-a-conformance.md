# Lane A: negotiated LSP operations and external processes

Baseline: See `bbccc32`. Evaluation: the revision containing this report on `spec-lane-a-tools`, Darwin arm64, Go 1.27.4. Baseline locations below refer to `git show bbccc32:<path>`, not current line numbers. Status follows [SPEC-000](../00-verification-framework.md): **implemented** means observed at the stated boundary; **partial** names the remaining limitation. These are requirement counts, not line coverage.

The evaluated paths are LSP initialization → negotiated request → shutdown/restart and `tasks.Run` → Go child process. Ripgrep discovery in the app now rejects resolved workspace executables, but its search process and Git commands do not use the Go-task policy handle. The common LSP launch guard applies to tsrs; no real tsrs run was verified. The test LSP peer is a real process speaking framed JSON-RPC over pipes; it controls advertisements, stalls, crashes and late replies. It is not evidence that every third-party language server behaves like that peer.

Reference: Apache OpenDAL `c0ce8b66` (implementation phase). A second, independent audit phase re-cloned the repository at `dfe9ddf1db14bba205d1df470378b3114e50a7a2` and re-verified the same paths. In both checkouts the core capability and error definitions live in `core/core/src/types/{capability,error}.rs`, layer composition in `core/core/src/raw/layer.rs`, and the retry, timeout, logging and chaos crates in `core/layers/`. Similarity of types is not an oracle: the task acceptance criterion is that a temporary failure before spawn can be retried, but no failure after spawn launches a second potentially side-effecting build/test.

This revision includes an adversarial audit of the original lane implementation: cited tests were checked for existence, and the epoch stale-session guard, the capability dispatch gate, the post-start no-retry rule, the workspace-executable launch denial, the stderr redaction and the outbox byte cap were each shown to fail their behavioral tests when the implementation line is removed. The audit extended the implementation in four places, noted per row below: permission-denied launch classification evidence (EXT-020), bounded redacted stderr capture (EXT-110/ERR-060), byte-bounded notification queueing (EXT-090), and plain-language presentation of trust-boundary denials in the settings and find surfaces.

A second adversarial round — the independent verification in [the verification-round section](#verification-round-verify-lane-a-commit-cb4ac34) below — then found three defects in exactly those audit-touched areas and the seam around them; their fixes are in this revision, with the new mutation evidence being: streaming redaction (oversize test fails when redaction is moved back after the trim), disk-spelling normalization (case-variant test fails when normalization is removed), and the Retry budget reset (its test fails when the reset is removed).

### RPC regressions: before and after

At `bbccc32`, `internal/lsp/jsonrpc.go:250,270-304` writes a request before reaching the caller's cancellation select; `:54-57` reads a header through newline before checking length. The same OS-pipe fixtures failed on the old implementation: **“cancel waits for peer to drain stdin”** and **“read beyond header limit”**, each at the one-second hang bound. In [conn_limits_test.go](../../../internal/lsp/conn_limits_test.go), the first peer reads one byte of a 2 MiB request and then stalls; cancellation now returns `context.Canceled` without requiring the peer to drain. The second sends 128 KiB without a newline or EOF; the reader now rejects it without waiting for either. Both passed, as did stalled initialize, unresponsive group shutdown, inherited stdout after leader exit, and a final reply immediately before exit:

```sh
go test -race -count=1 -v ./internal/lsp -run 'Test(CancelWithStalledPipe|HeaderLimitBeforeNewline|StartStalledPipe|ShutdownStalledProcessGroup|ProcessExitWithInheritedStdout|FinalReplyBeforeExit)$'
```

Six PASS, Darwin arm64. The process fixtures check kernel pipe/process behavior, not only in-memory RPC framing. Unix kills the private process group; descendants that deliberately leave it are outside the guarantee. Non-Unix fallback kills the direct child only. Closing the owned read end after a bounded drain prevents an escaped writer from hiding leader exit. Server stderr is bounded and secret-redacted into exit diagnostics rather than streamed; window messages log only severity. The digest trades raw server detail for not leaking credentials into log files.

## Verification round (verify-lane-a, commit cb4ac34)

An independent verifier re-checked every matrix claim against the cited tests, re-produced the mutation evidence, and ran adversarial probes of its own against real processes. Verdict was needs-fix with three required defects; the fixes and their evidence are folded into the rows above:

- **F1 oversize-secret leak** (REQ-EXT-110/ERR-060): fixed — streaming redaction before the window trim; oversize, split-write, and straddling secrets covered by tests, one end-to-end with a real process, mutation-verified.
- **F2 case-variant trust evasion** (REQ-EXT-030): fixed — containment decided in the disk's own spelling, probed per component with `os.SameFile`; mutation-verified. `internal/proc/diskspelling.go` mirrors Lane B's `workspace.DiskSpelling` shape and is marked to converge into it when both lanes land.
- **F3 custom-server denial misreported as missing** (REQ-EXT-020): fixed — all executable finders classify through the launch boundary's own `proc.ValidateExecutable`; explicit candidates (config command, `SEE_*` environment, managed installs) denied by the workspace trust boundary surface typed denials end to end, in the finders' errors, the settings pane, the toolbar and the failure notice.

Behavior-review dispositions: **F4** fixed (persistent budget exhaustion now names the server and the Retry remedy at every UI surface). **F5** fixed (manual Retry resets the crash budget; it is the user's deliberate act after remediation). **F6** fixed (Degraded recovers on the next successful sync and renders as its own toolbar state). **F7** accepted as-is (entry points discover unsupported on activation; the wire gate is the correctness boundary, pre-disabling is UX polish not worth the per-entry-point plumbing). **ERR-100** width accepted (conservative-legal, harmless).

The verifier's regression probes that pinned correct behavior are adopted into the lane's suites: `internal/lsp/verify_probes_unix_test.go` (escaped-descendant termination, shutdown escalation, stderr flood), `internal/langserver/verify_probes_test.go` (queue pressure, budget surfacing, close-before-overflow), `internal/tasks/verify_probes_test.go` (exit classification), `internal/app/verify_probes_test.go` (truncation visibility). The defect-demonstrating probes were re-implemented as positive tests next to their fixes.

## Additional entry points and verification

- `TestInvalidCapabilityHandshake`: real peers return missing/null/invalid capabilities or an unsupported position encoding. Startup returns a permanent error rather than making a client ready with guessed semantics.
- `TestRemoteFailureOnPipe`: an OS-pipe peer returns method-not-found, cancellation and an unknown code with a canary payload. `Conn.Call` retains the protocol code and operation but not the remote message or data. A local unsupported result instead has no effect and sends no frame.
- `TestFindRejectsWorkspaceRipgrepAlias`: a configured rg symlink outside the project points back inside. The app previously returned that path; now it returns no executable and a typed policy denial. With rg unavailable, Quick Open can still walk files (`TestListFiles`); text search requires rg. Missing gopls is handled separately by `TestFindGoplsSaysWhenThereIsNone` and the existing install hint in `App.lspFailure`.

App changes: `app.go` presents an unsupported operation as unavailable rather than a server failure; `tools.go` validates the effective rg binary; `codeaction.go` preflights command, URI and version requirements before edits; `symbolrename.go` propagates a rejected edit; `semantic_tokens.go` selects range requests for range-only peers. `tools_test.go`, `codeaction_test.go` and `harness_test.go` exercise/adapt those contracts. The audit phase added: `quickopen.go` renders permission-denied, trust-denied, not-installed and timed-out failures in plain words instead of raw error chains wherever a server or tool failure is summarized; `settings.go` distinguishes a denied workspace rg from a missing one; `navigator.go` explains the trust boundary in the find navigator instead of printing an internal error. No changes to Git, workspace identity, config or local history.
